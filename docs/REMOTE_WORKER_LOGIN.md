# Remote Codex reconnect

Outcome: the operator can renew the Docker worker's Codex subscription login from backoffice without sitting at its host.

Scope: a fixed Codex device-login request, durable operator-only progress, an allowlisted OpenAI verification link and one-time code, cancel/expiry/failure handling, subscription verification and readiness recovery. The worker polls Railway while its subscription is signed out. One login or review runs at a time; pairing credentials and provider access/refresh tokens stay in the private volume. Only the operator who starts this flow should enter its code.

Exclusions: arbitrary remote commands, password/token collection, automatic login, remote Claude login, code editing and API billing fallback. Claude retains its supported host CLI login. Backoffice session expiry continues to use its existing sign-in flow; signing back in recovers current worker status.

Acceptance: online current workers offer Reconnect Codex; queued/preparing/waiting states survive reload and transport retries; an unexpired code opens only the exact OpenAI device page; cancellation, expiry and terminal states hide and erase the code; a revoked worker or unrelated worker cannot update the request; login and review claims cannot overlap; CLI failure and missing device-login permission are actionable; a successful CLI login is verified before readiness returns. No raw CLI authentication output or credentials enter logs or customer APIs. Older workers remain compatible and explain the required upgrade.

Verification: PostgreSQL authorization/idempotency/concurrency/expiry tests, parser and child cancellation tests, actual pinned CLI device-output probe with fabricated/private home, Docker queue/control lifecycle checks, desktop/mobile reconnect and recovery flows, lint/typecheck/builds, and independent Staff Engineer, Product Owner and Product Designer reviews before commit/deploy. The real browser completion requires the operator's provider sign-in; do not claim it from a mocked test.

## Operator flow and release evidence

In backoffice, open Worker setup (or a project's Provider readiness), choose Reconnect Codex for the online idle worker, then Open Codex sign-in and enter the displayed one-time code. Keep backoffice open to see completion. If login fails, enable device-code login in ChatGPT Settings → Security or use the documented host command. Cancellation, expiry, revocation and terminal states remove the code. An expired backoffice session has a separate sign-in link and recovers the current request after sign-in. Older-format worker status explicitly disables remote login and cancels any pending reconnect during rollback.
