# Agent handoff and independent proposal comparison

Outcome: the operator can continue a private project review from Codex to Claude or from Claude to Codex, or request two independent scope/effort proposals and compare them before selecting an editable draft.

Scope: explicit handoff actions on validated replies; a Both agents comparison choice; atomically queued Codex/Claude jobs sharing one comparison ID, saved repository commit, request snapshot and operator instructions; private grouped comparison history; separate provider progress/failure/availability, scope, evidence, acceptance, assumptions/questions, effort/confidence and operator-rate cost/time ranges; selective draft import and continuation. One worker runs them sequentially; separately paired workers can handle the independent jobs. Human publication stays explicit.

Exclusions: code edits, executing customer code, binding quotes/dates, automatic publication, automatic provider fallback, API billing, native provider chat storage or hidden reasoning transfer. Comparisons are independent and contain no prior agent replies. Handoffs retain the existing bounded shared context (latest three validated summaries/scopes/assumptions and prompts) with a fresh source sample. Claude subscription setup is deferred at the user's request; the comparison support must work with honest waiting/setup states, without claiming a live Claude run.

Acceptance:

- Both handoff directions preserve the selected validated reply and current evidence, choose the destination provider explicitly, and reject stale/foreign/failed replies. Reload/auth recovery retains the pending request identity.
- A comparison queues exactly two jobs in one transaction and increments project version once. Retry with the same comparison ID returns those same jobs; changed operator instructions or another project conflict. An exact retry after customer inputs change still acknowledges the original pair, which is marked stale. An active review/comparison blocks a new unrelated run.
- Both jobs use the same pinned input and instructions and empty previous-agent context. Existing consent, connection, worker/attempt/lease and report validation gates apply to each independently. Cancelling a comparison stops only its unfinished jobs and keeps completed results.
- Only operators can read comparisons; customer APIs expose no prompts, drafts, activity or comparison metadata. Pair retrieval is project-scoped and works beyond the latest ten history entries.
- Desktop side-by-side and mobile stacked cards identify Codex/Claude, show each state and comparable scope/effort/confidence/cost/time, preserve a useful completed result if its partner waits or fails, and block stale imports/handoffs. Availability/setup guidance explains pending providers. Cost settings are shared operator choices; final quote/date and publication remain manual.
- Transport failures, reload and expired operator sessions reconcile the same group before allowing an exact retry. Status lookup failure never starts another group. Completed comparisons can be selected from loaded history; older turns remain available through existing pagination.

Verification: real PostgreSQL atomicity/idempotency/access/consent/claim/cancel/staleness tests and both-direction context tests; desktop/mobile comparison, error/partial/stale, exact retry/auth recovery and handoff checks; lint/types/builds; compatibility with the unchanged worker job contract; independent Staff Engineer/Product Owner/Designer reviews before milestone commit and deployment. Provider tests use synthetic output; an authenticated Claude subscription review is not claimed.
