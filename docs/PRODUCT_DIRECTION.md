# m8itwork product direction

Help people finish, fix, and take forward apps they have already started with AI tools. The pilot's goal is one paying development client. Custom features, integrations, and improved workflows are part of the offer, alongside launch help. Chat Florist is potential evidence of delivery experience, not a customer testimonial.

Latest positioning: “Built with AI. Let’s take it further.” Work with the existing app where possible; assess code ownership, export, backend dependencies, and platform access before proposing custom services or moving parts of the app. Avoid claiming that every app generator is incapable of extension or that every project needs to leave its platform.

Latest visual direction: a midnight workshop with dark navy scenery, slate panels, teal highlights, copper buttons, and original generated robot/folder figures. Remove the desktop shortcut icons and OS-style titlebar to distinguish m8itwork from its initial PostHog reference. See `docs/ART_DIRECTION.md` for the original prompts.

Milestone 1 is a service website, durable intake, and automatic read-only GitHub inspection. Private repository connection is non-negotiable for launch: register the App and verify a real private repository before declaring the pilot launch-ready. Private repositories use a GitHub App user token restricted by the app's read-only permissions and the user's selected installations. A demo URL and manual intake remain available for builders without exported code.

Inspection is bounded static evidence collection. It does not execute code, run tests, diagnose a working production app, or produce a binding project quote. Reports distinguish observed files from workflows still needing verification. Estimate assessment effort only; development effort and delivery dates need a human review of the demo and requested changes.

Milestone 1 excluded customer accounts. Milestone 2 adds a customer workspace: sign in, connect private GitHub, share issues/suggestions/PRD/requests, receive our review and proposal with ETA/cost, and follow delivery progress. See `docs/MILESTONE_2.md`. The latest user request authorizes Milestone 3: a protected admin, project conversation, mutually approved scope and upfront/installment payments through Stripe Checkout, then tracked work and verified handover. See `docs/MILESTONE_3.md`. Subscriptions, autonomous code changes, and automatically fetched demo URLs remain outside scope. Paid assessments and scoped project installments differ from Growth AI's subscription/usage-credit billing.

Latest navigation clarification: customers land on `/dashboard`, their owned-project overview and next actions. `/admin` is the operator's separate backoffice for customer requests and delivery; it has its own sign-in/queue and allowlisted access. Remove the in-place customer/team mode switch. See `docs/DASHBOARD_BACKOFFICE.md`.

Latest signup direction: customers can create a verified email/password or Google account without GitHub. A demo and project brief are enough to submit for the initial human review; private repository access can follow when agreed. Existing GitHub sign-in remains available. Google linking preserves an existing account only through a fresh authorization while signed in. See `docs/ACCOUNT_SIGNUP.md`.

Latest intake clarification supersedes demo-first onboarding: new projects need just a connected GitHub repository and a description of what the customer wants to fix, add, or move forward. Derive the project name and contact from the repository/account, inspect automatically, and send directly for our review. Remove the extra platform, demo, access-note, workflow, and contact questions. Existing draft projects and their history remain usable. See `docs/SIMPLE_PROJECT_INTAKE.md`.
